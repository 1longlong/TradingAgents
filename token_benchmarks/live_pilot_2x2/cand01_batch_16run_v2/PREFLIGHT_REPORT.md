### 1.1 What the independent audits changed about this verdict

The audits were not a formality: **two of them found defects that would have
silently invalidated the experiment.**

* **Audit B1** — the harness never read `spec["switches"]`. Under a neutral
  environment, **12 of the 16 delivered specs would have run with switches
  contradicting their own arm label** — every `C0` and `CC` run (which is the
  entire CAND-01 factor) and every `B` run. The study would have produced four
  columns of nearly-identical numbers and a confident, wrong conclusion.
  Fixed and mutation-verified.
* **Audit A-01** — the harness did not forward `FINNHUB_API_KEY`, the study's
  only news vendor credential. **All 16 runs** would have rendered
  `AUTH_MISSING` while the config claimed a working news path. Fixed.
* **Audit C-1** — a completion-model call raised inside the telemetry callback
  and disappeared from the event list. Pre-existing at RC1, but this is a
  *token* study, so a dropped call biases every arm. Fixed.

Had these audits not run, the honest verdict for this round would have been
**BLOCKED**, not `READY_WITH_LIMITATIONS`.

## 2. Limitation 1 — `dry_run` / refused-run semantics are absent from the delivered tree

**What the task asked.** Verify that `record_stopped` does not pollute attempt
numbering, that a refused run never creates `attempt_00`, and that the `dry_run`
stop path does not crash.

**What is actually true.** These behaviours lived in the **lost V1 script
bundle**. `scripts/token_benchmark.py` in the delivered tree contains no
`record_stopped`, no `attempt_00` handling and no dry-run stop path. There is
therefore nothing to test.

**Why it is not fabricated.** Writing a guard for a function that does not exist
would create the appearance of verification without the substance. The correct
statement is: *this round did not re-establish these semantics.*

**Impact on a paid pilot.** A refused run could, in principle, consume an attempt
directory or behave unexpectedly on the dry-run path. This affects run
bookkeeping, not the validity of a completed run's measurements.

**Next step to clear it.** Implement `record_stopped` and the dry-run stop path
in `scripts/token_benchmark.py` with tests, or confirm that the operator's driver
owns this behaviour.

## 3. Limitation 2 — `effective_config.json` is written by code not in this tree

The 16 V1 evidence files `…/attempt_01/effective_config.json` exist, but the
writer was in the lost bundle.

**What exists now.** Every V2 spec carries `switches`, `switches_source:
"declared"` and `config_sha256`; the child can verify them, and
`tradingagents/graph/switch_verification.py` (committed, tested) compares declared
switches against what the graph consumed.

**What is missing.** The artefact that records the *effective* configuration to
disk before the first paid call.

**Next step.** Add the writer alongside the verifier and assert that it refuses
to write when verification fails.

## 5. What was actually verified by execution

Each of these was run, not reasoned about:

1. **GDELT tripwire:** both the `gdelt_news` module attributes and the routing
   table poisoned to raise; the real analyst tools invoked with Finnhub forced to
   fail; **0 GDELT calls** recorded.
2. **AST proof:** no executable GDELT reference in either Finnhub route function,
   lazy imports included.
3. **Real graph:** `GraphSetup` driven for all four arms with a stub LLM; the
   analyst factories intercepted in `tradingagents.graph.setup`; declared
   switches match consumed switches. The wrong namespace was measured to
   intercept 0 calls.
4. **Fresh-interpreter switch delivery:** each arm's env vars applied in a
   subprocess; `DEFAULT_CONFIG` matches the arm exactly.
5. **Hash recomputation:** all 16 values recomputed from the documented
   algorithm and compared; 16/16 match and are distinct.
6. **Generator reproducibility:** `--check` reports *53 artefacts reproduce;
   16 differ only in volatile fields* (`timestamp_utc`, `git_working_tree_dirty`,
   `generator_sha256`); every hash-bearing artefact is byte-identical on a
   full regeneration at a different root (only the unhashed `results_dir`
   differs). Tampering produces exit 1 with `DRIFT`.
7. **V1 design parity:** all 16 V2 `cases` and `switches` equal V1's; execution
   order equals V1's pre-registered order.
8. **Mutation tests:** four source mutations, each caught, each file restored
   byte-identically (SHA-256 verified).
9. **Full suite + RC1 control:** final post-remediation matrix is
   `2 failed, 1990 passed, 2 skipped, 319 subtests` vs RC1
   `2 failed, 1471 passed, 2 skipped, 240 subtests`, with RC1 clean at
   `1473 passed` under `env -i`; 0 new failures (`logs/final_test_matrix.txt`).
10. **Protected state:** HEAD, tag, stashes, `.env`, 2446/2446 historical hashes.
11. **MANIFEST:** `sha256sum -c MANIFEST.sha256` — every entry OK; the manifest
    does not hash itself.
12. **Post-audit re-verification:** 8 source mutations (each re-introducing an
    audited defect) were caught; every file restored and re-hashed.

## 7. Recommendation

Authorise a paid pilot **only** after deciding on:

1. the budget posture (`null` cap vs a set ceiling);
2. the `dry_run` / refused-run bookkeeping (Limitation 1) — fix or accept;
3. the `effective_config.json` writer (Limitation 2) — fix or accept;
4. **committing the tree (Audit B2 / Limitation L8)** — the V2 generator, specs,
   tests and `switch_verification.py` are untracked at HEAD, so the study's
   provenance rests on this working tree plus `MANIFEST.sha256` alone;
5. **launch discipline (Audit A-00)** — every run must be launched from the
   repository root, because the shared `.venv`'s editable install resolves
   `tradingagents` to the main checkout regardless of cwd.

Items 4 and 5 are *preconditions of a trustworthy paid run*, not optional
polish. Items 1–3 are operator risk decisions.

These are operator decisions. None of them invalidates the code, the specs, the
hashes or the news scope, all of which are verified — which is why the verdict is
`READY_WITH_LIMITATIONS` rather than `BLOCKED`.
